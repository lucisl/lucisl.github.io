## 一句话

活动奖励不是"发个奖"，是**资金一致性**：重复发是资损，漏发是投诉；要靠唯一键、流水、状态机、回收队列、对账兜住。

---

## 1. 奖励状态机

奖励从"配置"到"到账"要经过：

```
配置 → 触发 → 发放 → 到账
              ↓
            失败 → 重试 → 死信 / 人工补偿
```

**关键原则**

- 先记账，再发奖：流水是事实，发奖是动作。
- 每次发放有唯一业务键：`order_no` / `trans_no`。
- 失败可重试，重试不重复发。
- 已发可回收：`canRevert` + 回收队列。

---

## 2. GET / USE 双流水

以魔盒赐福 `BoxBlessService` 为例：

- **GET**：发放流水，`trans_no = 队列 order_no`。
- **USE**：核销流水，`trans_no = 送礼批次号`。
- 发放：先插 GET 流水，唯一键冲突 = 已发放，直接返回；再插用户券（ACTIVE）。
- 核销：`UPDATE ... WHERE status='ACTIVE'` 单行原子，并发不会双消；成功后写 USE 流水。

**为什么双流水**

- 能查"发了多少、用了多少、剩多少"。
- 发放和核销解耦，退款 / 回收 / 对账都有据可查。
- 唯一键兜底幂等，不依赖"先查后写"。

**代码要点**

- `trans_no` 唯一键是幂等闸门；`DuplicateKeyException` 直接按成功处理。
- 发放在一个本地事务内：流水 + 用户券要么都成功，要么都回滚。
- 核销用条件更新，不用"先 select 再 update"。

---

## 3. 宝箱多级结算：唯一键 + 状态机 + Redis 标记

`GameBoxAwardHandler` / `GameBoxRankHandler`：

- 奖励记录先 `insert`，唯一键冲突 = 已处理。
- 状态：`PENDING → SUCCESS / FAILED`。
- 榜单累计：`orderNo + "_" + level`，一笔流水跨多级也幂等。
- 日榜 / 总榜结算：Redis 标记防重；异常时**删除标记**，允许后续补偿。

**难点**

- 多级奖励：同一个 `orderNo` 要发多个等级，不能因为唯一键把后续等级挡掉 → 加 level 后缀。
- 结算失败：不能把标记永久留着，否则永远补不了 → 失败删标记。
- 状态机：`PENDING` 是"已受理未完成"，`FAILED` 可重试，`SUCCESS` 不可重复。

---

## 4. 捕鱼：条件更新 + 唯一索引 + 溢出伤害

`GoldenFisheryFishHandler`：

- 扣血：`UPDATE ... WHERE id=? AND status='ALIVE'`，影响行数=0 说明并发/已死，放弃。
- 捕捞成功：再用 `WHERE status='ALIVE'` 抢"捕捞处理权"，防重复结算 / 重复发奖。
- 刷鱼：唯一索引保证一个房间只有一条活鱼；`DuplicateKeyException` / `DeadlockLoserDataAccessException` 后重查。
- 溢出伤害：一条鱼被打死，剩余伤害递归打新鱼；`orderNo` 加 `_depth` 后缀，保证每条鱼的榜单流水幂等。

**为什么不用分布式锁**

- 条件更新 + 唯一索引已经能抢处理权；锁只增加复杂度和失败点。
- 死锁 / 唯一键冲突是预期内的，捕获后重查即可。

---

## 5. 奖励回收 / 补偿

`AwardHandler.revert()` + `GiftAwardRevertQueue`：

- 发放记录带 `canRevert`。
- 回收走独立 `gift_award_revert_queue`，不和正常发奖抢资源。
- 回收失败可重试 / 告警 / 人工补偿。

**使用场景**

- 等级变化：用户等级降了，之前按高等级发的奖励要回收。
- 活动回滚：活动配置错了，已发奖励要撤回。
- 风控：异常账号的奖励要冻结 / 回收。

**原则**

- 回收是"另一条链路"，不要阻塞发奖。
- 回收也要幂等：同一奖励不能回收两次。
- 回收要有审计：谁、什么时候、为什么回收。

---

## 6. 对账与巡检

**三方对账**

- 配置：活动应该发什么。
- 榜单：谁应该得。
- 发奖记录：实际发了什么。

**巡检**

- PK 活动按阶段跑 `.check.ts`：查 `mod_common_round` 状态、榜单、奖励配置、`mod_common_award_record`。
- 差异输出：少了哪些 rank / 奖励类型 / 发放对象。
- 异常转缺陷 / 工单，人工补偿。

**指标**

- 发放成功率、失败率、重试次数、回收次数。
- 资损金额、差异条数、对账覆盖率。

---

## 7. 面试怎么讲

**"奖励怎么防重？"**

> 先插流水，`trans_no` 唯一键做幂等闸门；`DuplicateKey` 就是已发放。核销用 `UPDATE ... WHERE status='ACTIVE'` 条件更新，并发不会双消；失败走回收 / 补偿队列，定时对账。

**"多级奖励怎么防重？"**

> 唯一键加等级后缀，一笔流水跨多级也能幂等；状态机 PENDING/SUCCESS/FAILED，结算用 Redis 标记，失败删标记允许补偿。

**"捕鱼并发怎么处理？"**

> 条件更新抢处理权，唯一索引防重复刷鱼，溢出伤害用 `orderNo_depth` 保幂等，死锁 / 唯一键冲突重查兜底。

**"怎么定位资损？"**

> 配置 / 榜单 / 发奖记录三方对账；先止血（关活动 / 关发奖），再按流水和 trace 定位，最后补偿 / 回收。
