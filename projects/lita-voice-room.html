语音房与直播

Voice Room & Live

产品的主场景：用户进房、上麦、连麦、送礼、打榜，大房间再转推成直播。

  • 核心服务litalive / litaroom
  • 业务模块34 + 52
  • RTCAgora 声网
  • 数据停留 / 上麦 / 观看
← 返回 Lita 总览

这个域解决什么问题

语音房是 Lita 的主场景：用户建房、进房、上麦、连麦、送礼、打榜、退出；大房间通过混流转推成「直播」，让非 RTC 观众也能收听。

这个域同时决定三件事：实时体验（音视频、麦位、延迟）、消费场景（送礼、游戏、PK）、数据口径（停留、上麦、观看）。

角色与状态

  • 房间角色：房主 owner、主持 host、管理 manage、麦上用户、观众
  • 业务上的「主播」 = host + manage + owner（数据统计也按这个口径）
  • 房间状态：在线、麦位、锁麦、密码房、PK 中、直播中

一次进房链路

创建房间 → 主播上麦 → 用户进房 → 连麦 / 互动 → 送礼 → 房间榜更新 → 退出并记录停留。

直播与转推

  • Agora（声网）负责实时音视频，凭证走 Nacos thd-agora.yaml
  • agoramixcdn 把房间音频混流转推到 CDN，形成直播形态
  • 非 RTC 观众通过 CDN 收听，直播间数据与语音房分开统计
  • 直播间送礼在数仓里用 room_source = 'liveroom' 区分，语音房是 'voiceroom'

基础设施

  • 多个独立 Redis：在线状态、签名、房间状态分别部署，避免一个大 Key 拖垮全部
  • ES 双云：AWS / 阿里云两套 ES，用开关切换
  • Kafka：房间事件分发
  • WebSocket / 长连接：在线状态与房间消息

阅读路径与排查

  • 进房失败：litalive 的 liveauth / liveonline + 房间状态 Redis
  • 麦位 / 连麦问题：miclink
  • 直播看不到 / 卡顿：agoramixcdn、livestreamconverter
  • 榜单不对：liverank + 结算定时任务
  • 停留数据核对：dwd_once_room_stay_time → dws_voice_room_stay_time
